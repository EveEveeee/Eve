# 产品类型与拆解重心

先从用户目标、核心对象、主要反馈和价值交付方式识别主类型。类型可以混合，但要明确主次和因此改变的取证重点。

| 类型 | 识别信号 | 优先拆解 | 容易遗漏 |
|---|---|---|---|
| AIGC 创作工具 | 用户提供素材/提示，系统生成内容资产 | 输入约束、创作阶段、模型参数、生成任务、资产依赖、一致性、版本、计费、审核、预览导出 | 把 Agent 口头完成当资产完成；忽略参考素材的跨结果复用 |
| 通用执行 Agent | 用户给目标，系统规划并调用工具改变外部状态 | 目标分解、权限、计划/执行分离、工具契约、确认门、状态机、幂等、重试、中断、回滚、审计、完成验证 | 只分析对话文案；忽略真实外部副作用和失败恢复 |
| 对话陪伴 | 长期对话、人格关系、情绪价值、主动触达 | 人格设定、短/长期记忆、关系状态、情绪识别、边界、安全、隐私、召回、主动性、留存 | 把用户隐私当普通上下文；忽略记忆错误和依赖风险 |
| 工作流 SaaS | 表单、记录、状态流转、多人协作 | 角色权限、实体、审批、通知、集成、状态事实源、批处理、审计、导入导出 | 只拆页面，不拆数据权限和跨角色协作 |
| 搜索/知识产品 | 查询、检索、答案、引用 | 数据源、索引、召回/排序、时效、引用、权限、反馈闭环、幻觉治理 | 将生成答案等同于检索事实 |
| 内容社区 | 发布、消费、互动、分发 | 创作、审核、推荐、社交图谱、互动、治理、商业化 | 忽略供需两侧和内容生命周期 |
| 开发者工具 | 代码、项目、构建、调试、部署 | 环境、上下文选择、变更范围、执行权限、测试、版本控制、可观测性 | 忽略工作区隔离和破坏性操作风险 |
| 交易/决策产品 | 数据输入、分析、建议、下单或审批 | 数据时效、风险、解释性、授权门、合规、人工复核、不可逆动作 | 将建议和执行混淆；弱化高风险确认 |

## 混合类型处理

1. 以主要价值交付决定主类型，以关键风险决定次类型。
2. 例如“会生成素材并自动发布”的产品，主类型可为 AIGC，次类型为执行 Agent；既要分析生成资产，也要分析发布权限和确认门。
3. 报告开头说明类型判断、证据和对四层权重的影响。
4. 若证据无法区分类型，列出候选类型和需要补充的最小证据，不强行归类。
