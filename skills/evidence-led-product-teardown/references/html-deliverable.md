# HTML 交付规范

## 1. 文件要求

- 交付一个 UTF-8 `.html` 文件，标题包含产品或项目名称和“产品拆解”。
- 保持单文件可读；CSS 内嵌。若 Mermaid 使用 CDN，必须同时用表格或文字保存核心信息。
- 不内嵌敏感信息、Cookie、Token、鉴权头或不必要的个人数据。
- 页面应适配宽屏和移动端，表格可横向滚动，打印时不截断关键标题。

## 2. 推荐章节

1. 执行摘要与产品类型判断
2. 证据范围、准入状态与缺口
3. 用户层
4. 技术层
5. 模型层
6. 数据层
7. 端到端五流合一流程
8. Agent/模块、工具、模型、数据与资产关系
9. 核心数据实体及关系图
10. 当前架构 As-Is
11. 建议架构 To-Be
12. 关键风险
13. 组件—证据追溯
14. 未知事项与下一步取证

根据产品类型增减子章节，但四层不可缺失。若准入状态为 `BLOCKED_EVIDENCE`，HTML 仅包含证据诊断、缺口和采集计划，不伪造完整章节。

## 3. 可视化

至少选择真正有助于理解的图：

- 用户旅程或流程图：正常、修改、失败/中断；
- 时序图：用户、界面、Agent/模块、工作流、工具、模型、数据和资产服务；
- 四层全景架构图：用户层→技术层→模型层→数据层；
- ER 图或实体关系表：仅在数据关系足够复杂时使用。

Mermaid 主图要求：

- 同层组件放入同一 `subgraph`；
- 箭头标注调用、读取、写入、事件、确认、资产引用或状态更新；
- 实线表示【已确认】，虚线表示【合理推断】，强调色/粗线表示【建议设计】；
- 冲突或风险使用警示色；
- 提供图例；
- 组件旁附证据编号或在追溯表中建立一一映射。

## 4. 表格最低字段

端到端流转表：阶段、用户动作、处理者、读取、判断、工具/模型、输出资产、状态写回、确认门、失败分支、证据。

组件追溯表：组件、所属层、为什么需要、证据编号、结论等级、置信度、限制。

风险表：优先级、风险、触发条件、用户影响、证据、当前控制、建议控制。

## 5. 视觉编码

- 已确认：绿色或实线；
- 合理推断：黄色或虚线；
- 建议设计：蓝色或粗线；
- 未知：灰色或点线；
- 冲突/风险：红色。

颜色不是唯一信息载体，标签中仍写出证据等级。

## 6. 完成校验

保存后检查：

- HTML 能被解析；
- 目录锚点全部存在且 ID 不重复；
- 四层章节存在；
- 图例和证据等级存在；
- 所有主要结论都有证据编号或设计理由；
- Mermaid 代码块数量符合设计，关键内容另有文字备份；
- 没有产品专属模板残留、占位符或敏感信息；
- 输出路径可由用户点击访问。
